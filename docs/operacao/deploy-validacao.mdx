# Deploy e validacao

## Pipeline segura

O workflow `.github/workflows/ci-vercel.yml` executa lint, verificacao de tipos e o
build completo das duas aplicacoes em toda pull request. Um push na `main` somente
chega ao deploy depois que esse prebuild termina com sucesso.

O deploy recompila o admin com as variaveis de producao baixadas da Vercel, executa
`vercel build --prod` e publica exclusivamente o artefato gerado com
`vercel deploy --prebuilt --prod`. Dessa forma, uma falha de compilacao acontece
antes da publicacao.

Configure no ambiente `production` do GitHub estes secrets:

| Secret | Origem |
| --- | --- |
| `VERCEL_TOKEN` | Token de acesso da conta Vercel |
| `VERCEL_ORG_ID` | ID do time/conta proprietaria do projeto |
| `VERCEL_PROJECT_ID` | ID do projeto Vercel |

Para que esse gate seja efetivo:

1. Proteja a branch `main` e exija o check `Lint, tipos e build` antes do merge.
2. Configure o ambiente `production` do GitHub; se desejado, adicione aprovadores.
3. Desative os deployments automaticos da integracao Git da Vercel, evitando um
   deploy paralelo que contorne o workflow.
4. Use Node.js 22.x tambem nas configuracoes do projeto na Vercel.

As variaveis da aplicacao continuam cadastradas na Vercel. A CI de pull request usa
somente placeholders publicos para validar a compilacao e nunca recebe secrets de
producao.

## Deploy do app

Configuracao esperada na Vercel:

| Campo | Valor |
| --- | --- |
| Root Directory | `apps/petpage` |
| Build Command | `npm run build` |
| Output Directory | `.next` |

Quando o pipeline precisa incluir o admin em `/app-react`, execute o build da raiz ou garanta que `petCorner` foi buildado antes do `petpage`.

## Build local

```bash
npm run build
```

## Lint

```bash
npm run lint --workspace=petpage
npm run lint --workspace=petcorner
```

## Smoke test recomendado

Validar em producao ou preview:

- `/` carrega sem erro.
- `/produtos` exibe produtos ativos.
- `/produtos/[id]` abre detalhe e adiciona ao carrinho.
- `/cart` exibe item.
- login de cliente redireciona para `next`.
- `/checkout` mostra resumo.
- `/servicos` exibe servicos ativos.
- `/servicos/[id]` abre detalhe e aponta para agendamento.
- `/app-react` carrega o admin.

## Documentacao Mintlify

A partir de `docs`:

```bash
npx mint validate
npx mint broken-links
npx mint dev --no-open
```

`docs.json` deve ficar na raiz da pasta de documentacao, como exigido pelo Mintlify.
